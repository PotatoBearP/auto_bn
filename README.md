# Battle Nations 遭遇战助手

双击 `启动工具.cmd` 打开 Python GUI。使用 Python 3.10、Tkinter、Pillow，以及 Windows 自带英语 OCR。当前电脑已具备这些组件。

- **只识别**：切换到游戏，识别金色按钮中的 Attack，并核对卡片中的“感染者”，不点击。
- **识别并进入遭遇战**：选择匹配感染者的按钮，发送一次鼠标点击。多个匹配时选最靠上方的一个。

让游戏世界地图中的遭遇战卡片可见。窗口位置变化、焦点变化或目标区域变化时会停止点击。OCR 可能漏掉部分按钮；没有识别结果时不会点击。点击后的截图用于确认实际进入的游戏界面，发送点击本身不代表战斗已经开始。

GUI 和截图、定位、点击流程在 `app.py`。`battle-tool.ps1`、`native.ps1` 提供 Windows OCR 桥接，也保留独立 PowerShell 原型。程序不读取或修改游戏内存。

点击采用 Windows SendInput：鼠标用约 0.4 秒移动到目标，等待游戏处理移动事件，读取实际鼠标坐标确认到位，再按下约 0.15 秒后松开。`last-result.json` 保存目标与实际坐标，`game-hover.png` 保存点击前画面，`game-after.png` 保存点击后画面。目标区域变化仅表示画面变化，不能独立保证成功进入。

调试命令：`py -3.10 app.py --scan` 或 `py -3.10 app.py --enter`。

输出：`game-before.png`、`game-after.png`、`ocr.txt`、`last-result.json`。`detections.png` 中绿色框表示感染者，红色框表示未匹配感染者的按钮；`detections.json` 包含各卡片识别文字。识别可能漏检被遮挡的卡片。

## 重机枪手布阵

GUI 的“重机枪手 → 第一排 2、4 格”匹配可见单位栏图标，点选让单位进入默认格，再从脚下格中心按下左键，发送一次目标移动，松开左键。鼠标后端参考 [KeymouseGo 5.2.1](https://github.com/taojy123/KeymouseGo/blob/v5.2.1/Event/WindowsEvents.py)，使用 pywin32 的 mouse_event。

当前校准适用于约 1366×768，第一排靠近敌方，从左上到右下编号；目标格中心是 (489,335)、(709,445)。使用人物颜色特征核对摆放，暂不支持其他地图布局或分辨率。目标格已有单位时跳过，检查失败时停止；布阵成功后自动点击开战。

布阵还会加入单位栏第一架飞机（UH-1B 天禽），放到第一个机枪手正后方的后排第 2 格 (379,390) 获取经验。飞机生成格单独识别；目标格已有飞机时跳过，避免重复放置。使用尾翼和武器架特征核对位置，排除旋翼动画和选中高亮干扰。开战前必须同时通过两名机枪手和飞机的摆放检查；战斗决策仍操作机枪手。

输出 `deployment-complete.png`、`deployment-result.json`。命令行：`py -3.10 deployment.py`。

布阵后自动核对绿色按钮中的“开战”文字并点击一次，等待最多 20 秒检查按钮消失；加载期间不重复点击。`start-before.png`、`start-after.png`、`start-result.json` 记录开战过程。命令行只布阵可加 `--no-start`，已布阵时只开战可加 `--start-only`。

## 单次战斗决策

“分析并攻击一次”先点击机枪手脚下格中心，读取前两个技能的红色冷却背景，冷却技能不参与决策。一技能看人物命中轮廓；二技能看敌人所在棋盘格的亮蓝色主要伤害范围和黄色低伤害范围。黄色命中暂按 0.2 权重评分，并非实际伤害倍率；相近覆盖时参考血条比例。选中后只确认一次释放，等待攻击及敌方动画稳定，再结束本次操作。不会使用第三个对空技能。

前排死亡后单位推进，会依据当前血条和人物模板重新映射格子。按用户确认的游戏规则，当前可见敌人没有血条就按满血处理；不要求该敌人有初始或历史记录。显示血条时使用当前测量比例；完全灰色但仍有有效边框的血条继续作为存活目标。血条比例和范围覆盖为图像估计，并非精确生命值或伤害计算。当前只支持校准的感染者棋盘与两名机枪手。

本场已识别过的同类、同列敌人，在合理推进距离内允许技能高亮和姿态变化造成的模板偏差，仍需当前画面有对应人物，不沿用空格坐标。完全未识别到敌人时，取消旧瞄准并等待动画、重试最多 6 秒；仍失败才停止并保存固定的 combat-unrecognized.png。

命令行 `py -3.10 combat.py --preview` 只分析；`py -3.10 combat.py` 分析并释放一次。日志 `combat-result.json` 和 `combat-*.png` 记录冷却、模型、预览和攻击结果。

二技能在整个棋盘搜索独特蓝色双环，不依赖敌方位置或血条。从实际中心拖到目标后，等待至少 0.4 秒，重新定位中心，再完整按下、停留、松开鼠标。回合判断以底部技能 UI 为准：消失时停止输入，重新出现并持续可见至少 0.15 秒后读取下一回合，每次轮询间隔 0.06 秒。如果未观察到 UI 消失，则仍需确认攻击后的血量变化，并等待血量稳定至少 0.8 秒。一次释放后最多等待 25 秒观察敌方阶段与我方 UI 返回；结算界面出现时直接进入结算，不等待不存在的下一回合。

游戏已获得焦点时不再重复等待；进入遭遇战后由部署画面检测接管等待，开战后每 0.15 秒检测一次。结算确认后每 0.08 秒检查下一界面，识别到地图即可开始下次搜索。识别模板在进程内缓存；鼠标按下停留时间和二技能定位后的 0.4 秒等待保留。

图片已迁移到分类目录，详见 [图片目录说明](artifacts/README.md)。上述截图与日志文件名现在分别位于 `artifacts/runtime/encounter`、`deployment`、`combat`、`ocr` 中，运行时覆盖保存最新结果；开发截图归档到 `artifacts/development`，技能验证图放在 `artifacts/validation/skills`，模板位于 `assets/templates`。一技能专项验证命令：`py -3.10 combat.py --skill 1`。

GUI 的“确认战利品和经验，返回大地图”同时匹配结算标题及确定按钮，并动态检查它们的纵向位置，兼容增加经验单位后的面板高度变化及经验标题。界面持续稳定 0.25 秒才点击；点击后以界面实际切换为成功依据。若仍停留在同一结算界面，间隔至少 1.2 秒复核后重试，单个界面最多尝试 3 次。世界地图稳定可见 0.35 秒后继续搜索。命令：`py -3.10 settlement.py`。

## 全自动清理感染者

地图调整到需要的视野后，点击全自动清理。工具只扫描当前可见地图，不拖动地图。按从上到下、同一行从左到右选择第一个可识别的黄色或红色 Attack 入口，直接进入，不核对卡片名称；卡片标题被裁切也不影响进入。布置两名机枪手及后排飞机，开战后循环攻击，战胜后依次确认战利品及经验并返回地图，然后继续下一场。手动感染者识别仍核对名称。

一技能只要可用且有可命中目标就立即释放，跳过二技能的试瞄。两名机枪手的一技能都无法使用时，再预览二技能的蓝色主要范围及黄色低伤害范围，拖拽后等待 0.4 秒以上再完整点击中心。

二技能找到首个有可靠命中的瞄准位置就立即攻击，不再比较另一名机枪手或继续遍历剩余位置；当前机枪手冷却或所有候选位置均无命中时才检查下一名。

二技能每列只瞄准最前方的一名敌人，整列共用主要伤害覆盖，不再逐个试瞄后排。优先选择全列剩余血量比例总和最高的一列；总和相同时优先两侧溅射可覆盖更多剩余血量的列。当前血条提供血量比例，尚不区分不同怪物的最大血量。

二技能中心尚未出现时最多等待 6 秒，每 0.2 秒重试识别，期间不追加点击。如果动画期间我方技能 UI 消失，则等待 UI 返回并重新分析当前回合，不复用上一回合的瞄准位置。找到中心后仍保留定位后的 0.4 秒等待。

地图搜索兼容当前最小缩放：按按钮位置从上到下、同一行从左到右检查，自动清理找到首个 Attack 入口就进入战斗，不继续识别剩余卡片。缩小按钮原图 OCR 失败时，会提取白色文字再放大识别。

两名机枪手的一、二技能全部冷却时，再次核对四个技能的冷却状态及左侧“放弃”文字，点击一次跳过回合。观察我方 UI 消失并返回后继续决策；未确认回合切换则停止。预览模式不会跳过，范围识别失败也不会触发跳过。

地图拖动巡查功能已取消。当前画面没有可识别的 Attack 入口时结束，不再因卡片名称未确认或裁切而停止，也不把没有入口等同于世界地图已无感染者。布阵和二技能瞄准仍使用拖拽。

全自动排除猛犸遭遇战：匹配已知猛犸头像，或标题包含“猛犸”/“mammoth”时跳过该入口，继续找下一个。其他未知名称及裁切卡片仍可进入；没有可进入的非猛犸入口时结束。

游戏中按 **Esc** 停止，或者打开工具窗口点击“停止自动化”。切换焦点、移动游戏窗口、无法确认释放或回合状态时也会停止。冷却或识别异常不会通过连续盲点强行推进。每场最多 100 次攻击、战斗阶段最多 15 分钟。暂停后的游戏保持原状。

连续清理命令：`py -3.10 campaign.py`；开发排错后从当前战斗继续可加 `--resume`。旧参数 `--scope world` 也只扫描当前可见地图。单场命令仍为 `py -3.10 automation.py`。GUI 启动时自动开始连续清理可用 `py -3.10 app.py --replace-gui --auto`。

## 全自动 PVP 送分循环

感染者战斗的二技能瞄准增加容错：冷却或回合改变时重新分析，不继续等待已消失的蓝圈；瞄准缺失时最多重选技能两次，然后尝试另一机枪手。持续无法识别时取消瞄准并跳过当前回合，确认下一回合后继续。释放前仍保留 0.4 秒定位稳定等待及完整鼠标点击。

从基地地图点击 GUI 的“全自动 PVP 送分循环（哈哈笑 + 7 单位）”。每轮自动打开 PVP 并匹配（每 4 秒检测），进入部署后先发哈哈笑，再放 1 个重机枪手和 6 个大脚怪宝宝并点击开战。等待双方开始和我方可操作回合，机枪手存活时执行一次一技能横扫；若先被击杀则跳过横扫。之后每 3 秒检测并点击可用的放弃按钮，战胜或战败都点击确定，返回基地后自动开始下一轮。先后手依据实际操作 UI 判断。按 Esc 或 GUI 停止按钮结束，窗口或焦点改变也会停止输入。

命令行单轮：`py -3.10 pvp.py`；指定轮数：`py -3.10 pvp.py --rounds 5`；持续循环：`py -3.10 pvp.py --loop`。固定截图、单轮记录和累计循环记录位于 `artifacts/runtime/pvp/`，循环记录只保留最近五轮详情，避免持续积累图片。回归检查：`py -3.10 -m unittest test_automation test_campaign test_pvp -q`。

`artifacts/runtime/combat/campaign-result.json` 记录清理范围、已完成场数、目标和停止原因；`automation-result.json` 保留最新一场的详细攻击记录。地图巡查诊断位于 `artifacts/runtime/encounter/map-survey.json`。截图继续分类覆盖保存，不按回合累积。回归检查：`py -3.10 -m unittest test_automation test_campaign -v`。
